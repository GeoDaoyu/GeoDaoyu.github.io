Nginx基础-6:日志配置

Posted on 2026-11-25 Edited on 2026-11-27 In Nginx Word count in article: 1.2k Reading time ≈ 4 mins.

Nginx 的日志分两类：access_log 记录每个请求，error_log 记录 Nginx 自身的错误。默认 nginx.conf 里那段 log_format main 加 access_log，就是最常用的起点。

这段配置只做了两件事：先用 log_format 定义一个名叫 main 的格式，再用 access_log 指定把日志写到 logs/access.log，并采用 main 格式。

两类日志

日志 指令 记什么 默认值
访问日志 access_log 每个请求一行：谁、什么时候、请求了什么、结果如何 logs/access.log，格式 combined
错误日志 error_log 启动、连接、上游、配置等错误和警告 logs/error.log，级别 error

访问日志是排查业务和做统计的主要来源，错误日志用来定位 Nginx 本身的问题。两者配合看，才能还原一次请求的完整过程。

log_format：定义格式

语法：

  • 只能写在 http 块里。写在 server 或 location 里会报 "log_format" directive is not allowed here。
  • name 自己起，后面由 access_log 引用。
  • 格式串由普通字符和变量拼成，变量以 $ 开头；多行写法是用空格拼接多个引号字符串，最终还是一整行。
  • escape 控制变量里的引号和特殊字符怎么转义，默认 default（非 ASCII、特殊字符转成 \xXX）；要输出 JSON 时用 escape=json。
  • 某个变量在当前请求里没有值（比如没有 Referer），会记成 -。

变量 含义 上面这行的值
$remote_addr 与服务端直接建立连接的客户端 IP 192.168.1.20
$remote_user HTTP Basic 认证的用户名，没有就是 - -
$time_local 本地时间，Common Log Format [25/Nov/2026:20:31:07 +0800]
$request 请求行：方法 + 路径（含参数）+ 协议 "GET /api/user?id=1 HTTP/1.1"
$status 响应状态码 200
$body_bytes_sent 响应体字节数，不含响应头 532
$http_referer 来源页面 "https://example.com/"
$http_user_agent 客户端 UA "Mozilla/5.0 ..."
$http_x_forwarded_for 代理链上的客户端 IP，直连时是 - "203.0.113.9"

几点容易混淆的：

  • $body_bytes_sent 不含响应头，$bytes_sent 含响应头，做流量统计时要注意用哪个。
  • 请求经过反向代理后，$remote_addr 是上一跳代理的 IP，真实客户端 IP 要看 $http_x_forwarded_for（或配合 realip 模块改写 $remote_addr）。
  • $request 带查询参数，密码、token 之类的敏感参数会原样落盘；只想要路径可以用 $uri（不含参数）。

配置访问日志

语法：

  • 上下文：http、server、location、if in location、limit_except，所以可以全局记一份，某个 location 单独记一份。
  • 同一层级可以写多条 access_log，同时输出到多个文件或 syslog。
  • 不写 format 就用 combined。
  • access_log off; 关闭当前层级的访问日志。

缓冲写入

高并发下每条日志一次写盘开销不小，可以开缓冲：

  • buffer=32k：攒够 32K 再写。
  • flush=5s：即使没攒满，最多 5 秒也落盘一次。
  • gzip：写入前压缩，默认 64K 缓冲、压缩级别 1，zcat 可以直接读。buffer 和 gzip 不要同时写，gzip 本身就带缓冲。
  • 缓冲的代价是日志有延迟，nginx 退出或重新打开日志文件时才会把剩余内容刷出去，排查正在发生的故障时可以先不加缓冲。
